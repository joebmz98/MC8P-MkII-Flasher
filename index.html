How to flash

  1. Connect the board with a USB‑C data cable (plug it straight into the computer, not a hub).
  2. Put it into DFU mode: hold BOOT0, tap NRST, keep holding BOOT0 for about one second, then let go. You can also hold BOOT0 while plugging the cable in. These boards sometimes need two or three tries. In DFU mode the OLED stays blank.
  3. Choose the firmware below, click Flash Firmware and pick STM32 BOOTLOADER in the popup.
  4. Wait for Done. The controller restarts by itself. If it does not, press NRST once.

Troubleshooting

STM32 BOOTLOADER is not in the list

The board is not in DFU mode yet. Repeat step 2, try a different cable (many USB‑C cables are charge only) and plug directly into the computer. On Windows, Device Manager should show STM32 BOOTLOADER while it is in DFU mode.

Windows: "Access denied" or "Unable to claim interface"

Chrome can only talk to the bootloader through the WinUSB driver. Download Zadig, put the board in DFU mode, choose Options > List All Devices, select STM32 BOOTLOADER, pick WinUSB and click Replace Driver. This is needed once per computer.

Linux: the device appears but cannot be opened

Add a udev rule so your user can access it, for example SUBSYSTEM=="usb", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="df11", MODE="0666" in /etc/udev/rules.d/50-stm32-dfu.rules, then unplug and replug the board.

"USB transfers keep failing" or "A transfer error has occurred"

The flasher already retries with smaller USB blocks automatically. If it still fails, swap the cable, try another USB port or a powered USB hub, and unplug other USB devices. Adding ?block=256 to the page address starts with small blocks straight away.

It flashed, but the controller does not start

Make sure BOOT0 is released, then press NRST or unplug and replug. If the LED next to the USB port keeps blinking quickly, the board has the old WeAct HID bootloader on it; press NRST once more. If it still does not start, click Download Log and send it to us.
